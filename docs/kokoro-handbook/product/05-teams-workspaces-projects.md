# 站点、工作空间、项目和会话

状态：2026-10-05。当前业务规则以 [当前 PRD](09-v2-prd.md) §3–5 为主；本章节补充组织关系，不定义新的 schema 或角色系统。

## 普通用户的对象关系

- 普通持久会话区始终展示；项目像一级文件夹，每行独立展开，其会话缩进在该项目下。进入项目不替换普通列表，也不另列侧栏“当前专案会话”区。展开只控制显示，项目名称/会话叶子分别导航；细则以当前PRD §3为准。全集搜索标注归属，不复制会话。
- 会话可无项目，也可归属一个项目；现目标以可空 `project_ref` 表达，不新增会话绑定实体。
- 移入/移出/项目间移动保持同一 ID、消息及历史；确认回执后列表和路由一致，迟到请求不串 scope。
- 项目是相关会话、指令和资源的组织单位，不是执行 Run、独立定时任务或付款账户。
- 定时任务有自身列表、CRUD、调度和生命周期；项目关联不令其进入会话列表。
- 项目删除采用用户批准的 ChatGPT 语义，范围及官方来源见 PRD §3；独立任务的联动政策待用户裁决，不擅自连带删除。
- 点击项目/新建入口不自动产生消息、模型调用或扣费；新建草稿与持久会话分开。

## 隔离和授权

默认个人私有、显式分享。放进项目不自动向整个团队公开；只有项目的有效显式授权才开放声明资源/动作。
同 tenant 是隔离范围，不是访问许可；同团队的另一成员和跨 tenant 均须有系统负例。
前端呈现普通用户/管理员即可；IAM 内部成员、邀请、角色及资源权限不因此删除或简化为前端开关。
管理员管理成员不默认获得读取私人会话/文件权限，跨站管理也须明确授权与审计。

## Site / Workspace 的产品含义

Site 是产品实例；Workspace/Team 是授权协作范围；Project 是内容组织单位。用户不需要学习内部 Host/Runtime/Policy 抽象。
这些对象的事实 owner、标识和生命周期由现架构与各 owner 三面决定，不从旧目录或图示推导新对象。
多站点、企业白标以及 Music/Video/Image/Code 专业项目形态属于长期专题；不作为本轮额外前端建设要求。
