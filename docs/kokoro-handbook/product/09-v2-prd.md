## 1. 产品问题与目标用户

用户需要的是可持续使用的 AI 工作空间，而不是登录演示、孤立组件或只能跑一轮的聊天。
当前痛点是：入口/加载状态不稳定，会话与项目及独立任务混淆，能力展示和真实执行脱节，积分与失败恢复尚未闭合。
本次把已有目标收敛成可验收的用户流程，不新增服务、抽象或第二套业务系统。

- 普通用户：登录、聊天、管理自己的会话与项目、使用授权能力、管理文件及定时任务、查看积分。
- 管理员：在授权范围管理成员、能力、模型路由及正式积分；不是默认读取所有人的私人对话。
- 团队成员身份不自动开放个人数据。资源分享和管理权限仍由 IAM/事实 owner 校验；前端不让用户学习内部权限术语。

## 2. 当前研发范围与非目标

|范围|约束|
|---|---|
|唯一当前前端|`apps/kokoro-app`；其它前端不参与本轮改造|
|完整能力范围|正规登录、Home/Composer、会话/项目、独立定时任务、文件/作品、Agent/Todo/工具/子Agent、审批、Skills/MCP、Settings、管理能力、正式积分与最终支付|
|交付顺序|先可真实使用的聊天旅程；独立 owner 能力并行推进；全部 Wave 0–7 保持，支付渠道最后|
|专业 Studio|音乐/视频/图像/代码专题描述长期形态；不据其旧示例增加本轮独立 Studio 前端或承诺未接通的生成能力|
|不属于本轮研发扩展|部署运维的多角色数据库、集群、网络策略及渠道生产配置；不把这些变成聊天开发的前置工程|
|旧实现|无旧数据/代码兼容要求；切片承接有效安全与一致性职责后删被替代路径，不留下 fallback/alias/双轨|

“参考 ChatGPT/Manus”指成熟的聊天阅读、导航、过程反馈和恢复体验；不意味着复制全部功能、内部角色或未经批准的产品范围。

## 3. 核心业务对象与交互关系

|对象|用户理解|关系与边界|
|---|---|---|
|会话 Conversation|连续聊天历史|可独立存在，也可归属一个项目；唯一归属为可空 `project_ref`，不新建绑定实体|
|项目 Project|组织相关会话和资源|不是执行任务或付款账户；进入项目展示该项目概览与会话，不创建幽灵会话|
|执行 Run|一轮消息背后的执行|排队/运行/审批/取消/完成/失败；不与长期会话或定时任务混为一个对象|
|定时任务 ScheduledTask|按时间自动运行的独立任务|有自身列表与生命周期，项目关联不把它变成会话；Occurrence 结果可进入授权会话/产物路径|
|文件/作品|上传的资料、实际生成的结果|持久对象与引用由对应 owner 管理；卡片必须有真实回执，不由浏览器凭空生成|
|Skill / MCP 连接|可复用能力 / 外部授权连接|目录可见、个人安装/启用、已连接、运行时已加载是不同状态；选中不等于已执行|
|积分账户/流水|余额、预占与实际费用|Billing 唯一账务权威，浏览器只展示正式结果，不自己维护倍率或余额|

### 会话列表和项目

1. 外部普通会话区在Home、项目及其他模块页面始终存在，展示无项目归属的持久会话，不因当前project scope被替换或隐藏。项目区为文件夹式导航：每个项目行有独立展开/折叠控制，其所属持久会话缩进在本项目下；多个项目可同时展开，不再保留侧栏的独立“当前专案会话”区。项目只是一级组织单位，不新增项目子目录实体。
   - 展开/折叠与选择分别建模：展开控制不切当前URL/正文/草稿、不创建会话；点击项目名称进入项目概览，点击子会话打开该项目的原会话。普通区会话打开普通会话路由。当前活动项目的子会话在其所属项目下可定位，但不能据active推断用户已展开其他项目。
   - 普通区与每个已展开项目的加载、合法空、错误/重试、分页状态独立。未加载/失败不冒空；慢或迟到结果不能替换别组或抢当前选择。折叠不改变会话project_ref，不影响仍打开的正文；跨刷新记忆展开偏好不作为本轮新增要求。
   - 全集搜索仍可检索本人有权访问的两类会话并标注归属。会话移动只在owner确认后刷新原组与目标组，保持同一ID/历史；未发送草稿不冒持久列表行。
2. 新会话先是草稿；只有用户明确发送才创建持久消息/执行。点击新建、Home 提示或项目入口不自动调用模型/计费。
3. 移入项目、移出项目、项目间移动保留同一会话 ID 和消息历史；权威回执后更新列表、URL 和上下文，不复制会话。
4. 新建、改名、归档、删除、移动分别有明确菜单与空态。加载中不是“不存在”；空标题/重复快捷入口不冒真实会话。
5. 删除项目采用用户批准的 ChatGPT 规则：删除项目及项目内会话/指令和仅属项目的文件；单独保存在 Library 的文件保留。必须明确不可恢复范围并确认，不能默认把内含会话移到外部列表。
6. 项目删除、活动执行、资源引用释放及独立定时任务的关系必须有系统验收；独立定时任务删除/暂停/解绑政策尚待用户裁决，不自行连带删除。

第 5 条参照 [OpenAI Projects 文档](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) 的删除语义，核验于 2026-10-04；不照搬其物理保留周期或团队产品范围。

## 5. 用户状态与异常交互

- 发送前草稿 → submitting → queued → streaming → completed / failed；审批进入 awaiting approval，决策后 resuming。
- Stop 进入 cancelling，只有持久执行终态确认才展示取消完成；未知回执先对账，不盲目再次发送。
- 断线进入 reconnecting，恢复原会话；网络状态不覆盖持久执行状态，不把 partial 内容当成功终态。
- 加载必须有既定期限和终态。原列表/草稿能保留则保留，就近错误与重试，不用整页无限 loading 代替错误处理。
- 切会话/项目/设置/账号时，旧请求晚到不覆盖新范围；卸载不泄漏订阅，多个订阅者不互相关闭连接。
- 空内容、超限、权限拒绝、连接撤销、余额不足、模型不可用、超时、未知提交分别显示可理解结果，不统一成“重试一下”。
- 不存在重试 API 的已终态任务，不放一个假“重试”按钮；恢复、重新提交和重放幂等命令有不同语义。

## 6. 研发约束与依赖

PRD 不定义 SQL/wire 字段；技术方案、API 和数据模型由既有 owner 三面约束。
Browser→Web同源→BFF→事实 owner；BFF 持久会话/项目与 AG-UI，Agent 持久执行，IAM 管身份，System 管模型技术路由，Platform 管 Skills/MCP，Storage 管对象，Scheduler 管调度，Billing 管资金。
Web 使用成熟组件与现有设计 token；组件库/AI SDK 能力不替代业务验收。不为了统一名称新增服务或第二协议。
本地一个应用数据库、同凭据、独立 owner schema；共享 Redis 分命名空间。禁止跨 owner SQL 和重置共享数据。

|关键依赖 / 风险|负责人|当前事实与动作|

|正式预占/执行/用量/结算链|Billing、Agent、IAM、System / Root|R199 IAM 制品构建门通过仅为前置；实际金额、授权和用户流水仍待验|

## 8. 退出标准与尚待裁决

- 每项功能覆盖主链、边界、异常、权限、生命周期与刷新/跨页/跨窗口；系统测试记录预置、步骤、预期、实际和版本。
- 必要真实模型、PG/Redis/对象存储/owner与浏览器链有当前证据；mock、组件或单仓工程门不替代。
- P0/P1清零，完整目标和必要验收通过，资源回收可证明，运行组合与已验版本一致，才称完整正式。
- 保留失败历史与未验状态；故障注入用自有资源，不清共享数据，不泄露密码/key/正文。
- 待用户裁决：删除项目时独立定时任务保留、暂停或解绑规则；运行组合升级时现测试对话的保留选择。分别关联既有 T-C05/T-P05 和 R197-W2-release，不阻塞无依赖工作。
- 采购费率、币种换算及舍入须由正式 Billing 配置/设计绑定并真实核验；未确定值不填造，不扩成第三定价服务。
