## 版本主题

**通用对话从"演示可跑"到"敢给真实用户"。**

V1 交付了完整闭环（消息→执行→HITL→恢复→产物）与全量验证马具；
V2 不加大功能面，把"真实用户上来就会撞到的墙"逐一拆掉。

## 用户可感知目标（按优先级）

```text
G1 有身份：登录后才有会话；我的会话/文件只有我可见。
   ——当前所有端点无鉴权，是公开部署的硬闸门。
G2 失败讲人话：这一轮为什么没成（预算超限/配置错误/内部错误）、能不能重试、
   一眼可读；不再是笼统的"没能完成"。
G3 能力看得见管得着：Launcher 里的 Skills/MCP 入口可浏览本空间已启用能力
   （消费 06 号手册的呈现），会话里用到哪个 skill 过程块里可见。
   skills 多挂不再拖慢/挤爆上下文（技术面：渐进披露）。
G4 语言可切换：中/英静态文案切换（界面语言≠模型回复语言，后者跟随输入）。
G5 运营可配置：platform 后台能看到（进而能改）每个 namespace 的入口/能力
   配置与资产，改动不再走改文件+重启的工程师通道。
```

## 明确不做（本版）

```text
music/video/image/code studio 的任何功能实现（垂类另有专属手册与排期；
  本版只保证"新增一类 agent"的工程成本≈一个包+一行注册，属技术就绪门）。
skill/MCP 的市场化（上架/审核/计费）——Hub 是 platform 后续故事。
团队协作面（多人同 workspace 实时协同）。
界面动态文案的运营编辑面（随 platform 后台下一波）。
```

## 成功判据

```text
一个未参与开发的用户，注册→对话→触发审批→批准→拿到文件→刷新不丢，
全程无需任何工程师侧协助或解释。
运营在后台改一个 namespace 的技能授权，用户下一轮会话生效，无发版。
任何一轮失败，用户凭失败卡文案自行判断"该重试还是该找支持"。
```

## 度量（发布后看什么）

```text
会话完成率（run.completed/全部 run）与失败码分布（internal_error 占比应持续走低）。
HITL 暂停的人工响应率与放弃率（不回答，停止本轮 的占比）。
刷新/断线后的会话恢复成功率（水合失败告警应为 0）。
```
