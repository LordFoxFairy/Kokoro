# Web i18n 能力边界（高层技术判断）

- 状态：判断定案，实现未启动（2026-07-05）
- 性质：本文只回答"web 侧 i18n 应该具备什么能力、边界在哪"。**不规定**目录结构、
  namespace 划分、页面声明方式、组件 API——这些由 web 侧实现时自行深度思考。
- 关联：`docs/homepage-i18n/README.md`（首页规划交接，其 i18n 段由本文接管）、
  technical/05（web 架构）

## 现状事实（判断的地基）

```text
web 42 个非测试源文件硬编码中文——不存在静态 i18n 层，换语言=改代码发版。
契约 run.failed.error / tool 错误文案是自由文本 string——后端吐什么语言前端就
  显示什么语言，web 无法本地化、无法分租户呈现（跨仓边界缺陷，见"风险"⑥）。
web 无 locale 概念：无语言协商、无用户切换、无持久化。
曾出现的 admin/i18n workbench + api/i18n/preview 已撤除：把"运营编辑面"塞进
  web admin 是形态错位——编辑面属于 platform 后台既定方向（配置表后台管理），
  web 只做消费端；且 preview/workbench 属"暂不做"清单。
```

## 一、web 侧 i18n 应具备的能力

```text
语言协商与持久化   浏览器偏好 + 用户显式切换 + 跨会话记忆，一处决定全站 locale。
静态资源供给       构建期生成的语言包按 locale 供给，首屏零额外翻译请求。
动态覆盖供给       运行时按 locale + 作用域批量拉取覆盖集（一次拉一包，绝不逐条请求）。
统一解析层         渲染时唯一取词口：动态覆盖 → 静态资源 → fallback 链，调用方无感知来源。
格式化能力         插值、复数、日期/数字/货币（ICU 语义）；RTL 只留位不实现。
缺失可观测         dev 显性标出缺失 key，prod 静默走 fallback 并可上报；永不裸露 key 给用户。
缓存与失效         动态覆盖带版本锚（etag/version），可长缓存、可即时失效。
```

## 二、静态 i18n 与动态 i18n 的职责差异

```text
静态：产品固有文案（导航/按钮/表单/错误模板/空态）。
  生命周期=发版；构建期可校验完整性（缺 key 直接红）；性能最优；按 locale 分包控体积。
动态：随运营节奏变化的内容（公告、活动文案、定价话术、租户/白标定制、实验文案）。
  生命周期=运行时；platform 后台改完即生效；量小、按作用域批量下发。

判据一句话：这段文案改动需要发版吗？需要 → 静态；不需要/按租户不同 → 动态。
量级预期：静态是主体（>95%），动态是薄薄一层覆盖。倒过来就是设计跑偏。
```

## 三、渲染协同（固定资源 + 动态覆盖）

```text
静态包先行：页面凭静态资源即可完整渲染，动态覆盖是非阻塞增强——
  覆盖集未到/拉取失败，页面照常（显示静态文案），绝不白屏等翻译。
覆盖以补丁集到达：进入某作用域时一次批量拉取该 locale 的覆盖包；
  覆盖集为空是常态路径（零成本走静态）。
切换语言 = 换静态包 + 重拉该 locale 覆盖集，同一解析层语义不变。
```

## 四、风险清单

```text
① 性能：动态请求进首屏关键路径 → 必须非阻塞；静态包按 locale 异步分包，不进主 bundle。
② 缓存一致性：覆盖改了不生效/多 pod、CDN 呈现不一致 → 覆盖包必须版本化，禁裸缓存。
③ 缺失文案：fallback 链要一次定死（如 zh-TW → zh → en → key 的兜底顺序）并全站唯一；
   静态缺失在构建期拦，动态缺失在运行期兜底。
④ 构建体积：全语言打进主包是最常见事故 → 语言包必须可拆分按需装载。
⑤ 运营覆盖是不可信输入：错 key、插值参数不匹配不得崩渲染——坏覆盖单条丢弃回退静态
   （web 仓 Zod .catch 兜底铁律的直接应用）。
⑥ 跨仓边界（前置缺陷）：契约里错误应以稳定 code 为准、人读文案为辅，web 按 code
   本地化——否则动态内容永远混着后端语言。此项动契约，须单独裁决排期，不随 web 侧启动。
```

## 五、暂不做（防过度设计）

```text
不扩 platform i18n core；admin/后台 UI 不做多语言。
不做 preview/workbench（web 与 platform 都不做）；动态覆盖的编辑面待 platform
  后台管理方向排期，届时 web 也只是消费接口。
不做逐条运行时机器翻译；不做 TMS/翻译工作流集成。
不做 SSR i18n 注水一致性（当前形态用不上，做了就是白重量）。
不做组件级动态声明协议——静态层稳住之前，任何"每组件声明自己要哪些 key"的
  机制都是过早抽象。
agent 产出内容（模型回复）的语言不属于 UI i18n——那由 prompt/模型决定，别混进来。
```
