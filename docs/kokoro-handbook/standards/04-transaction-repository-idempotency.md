单语句原子写无需额外事务框架；多语句不变量使用同连接本地事务，外部服务调用不包装成伪跨库事务。

## 每个可重试用例的设计卡

| 决策         | 需要明确的内容                                               |
| ------------ | ------------------------------------------------------------ |
| 操作身份     | 租户、操作名、幂等键的作用域，以及是否由资源状态天然保证幂等 |
| 重复请求     | 同身份同参数返回什么；不同 digest 如何冲突                   |
| 并发执行     | 唯一性/条件写/锁如何决定唯一有效结果                         |
| 结果未知     | 网络中断后如何查询首次结果，而不是盲重试                     |
| 保留窗口     | receipt 与事件保留多久，过期后是否允许重新执行               |
| 跨系统副作用 | outbox、接收方去重与补偿；提交事实和发送之间崩溃如何恢复     |
| Redis 故障   | 仅加速可回源、部分功能暂停，或关键依赖失败时拒绝新执行       |

GET/HEAD、按已删除状态收敛的 DELETE 和确定性状态设定可按契约天然幂等；不为所有写操作机械建 receipt 表。
Redis 去重/lease 是协调机制，持久化业务结果仍由 owner 数据库约束与状态收敛证明。

验证必须包含重复、并发、事务回滚、提交结果未知、进程重启和适用的依赖故障；异常返回值或单元 mock 不证明数据库原子性。
