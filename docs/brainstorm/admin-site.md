# Admin IAM/Site 管理体验 PRD（评审稿）

> 本稿位于父仓库评审区。后端契约通过验收后，结合最终 API 修订并提升到
> `kokoro-web/apps/admin/docs/product`，提升前不得作为实现权威。

## 1. 产品目标

为平台管理员提供完整、稳定、高密度的 IAM 与 Site 管理工作台。它不是运营看板，也不是
把所有内容铺在一个页面的演示页。用户应能快速扫描、筛选、进入详情、完成命令并返回原位置。

设计基座固定为 Next.js App Router、Ant Design 6、Ant Design Pro Components 和 Lucide/Ant
内置语义图标；不再手写已有的表格、筛选器、弹窗、抽屉、权限树或布局框架。

## 2. 信息架构

```text
工作台

身份管理
- 用户管理
- 管理员管理
- 登录与会话

租户管理
- Site 管理
- Site 成员

组织管理
- 组织管理
- 组织成员

权限管理
- 角色管理
- 权限目录
- 菜单与路由
- 授权检查

安全与审计
- 登录日志
- 操作日志
- 安全事件

系统管理
- 认证策略
- Session 策略
- 系统状态
```

菜单只能在对应 `route → generated RPC → 服务端授权 → 审计 → 自动化测试` 全部存在后注册。
普通用户没有管理入口；Site 管理员只看到当前 Site 范围；平台管理员可显式跨 Site 查询。

## 3. 页面模板

- 列表页：`PageContainer + QueryFilter + ProTable`，筛选区默认一行，复杂条件展开。
- 详情页：摘要头、状态和主命令；下方使用 Tabs 分离概览、成员、角色、会话、审计，不纵向铺满。
- 编辑：少字段使用 `ModalForm`；复杂授权使用 Drawer；危险命令使用二次确认并要求原因。
- 权限：左侧角色列表、右侧分组权限树；变更摘要固定在底部操作条，不嵌套卡片。
- 日志：独立筛选表格和详情 Drawer；详情展示结构化字段，不直接倾倒 JSON。
- 工作台：只展示真实聚合数据和待处理风险，不使用虚假指标或营销式大卡片。

## 4. 视觉系统

- 方向：浅色、高密度、克制的企业后台；信息层级来自网格、分隔线和留白，不依赖大片卡片。
- 画布 `#f5f7fa`，表面 `#ffffff`，正文 `#1f2937`，次文 `#667085`，边框 `#e5e7eb`，主色
  `#1677ff`；成功、告警、危险色只表达状态。
- 侧栏 216px，顶栏 56px，桌面内容内边距 20–24px；组件默认 `size="small"`。
- 圆角 6px，卡片上限 8px；页面 section 不做漂浮卡片，不允许卡片嵌套。
- 图标统一 16px，折叠菜单 18px；所有命令使用语义图标，陌生图标提供 Tooltip。
- 页面标题 20px，section 标题 16px，正文 14px，辅助文字 12px；禁止随 viewport 缩放字号。
- 路由切换、Tab 切换、筛选展开必须保持壳层和主内容基准稳定，不产生宽度、高度或按钮跳动。

## 5. 组件与代码边界

```text
components/platform   页面、详情、命令栏等薄封装
components/data       表格、筛选与分页统一策略
components/forms      原因、版本、状态等复用字段
components/feedback   错误码映射、命令结果、空/错/加载状态
modules/iam/*         用户、管理员、认证、审计垂直模块
modules/site/*        Site、成员、Site 授权垂直模块
```

Server Component 负责读取；Server Action 负责命令；Client Component 只承担表格交互、表单和
局部状态。生成消息不得进入展示组件。后端返回稳定 error code 与 message，前端按 code 决定
字段错误、Toast、Alert、冲突刷新或权限页。

## 6. 完整状态

每个页面必须具备 loading、empty、error、permission denied、version conflict、deleted、
partial data 和成功反馈；每个命令明确提交中、不可重复点击、幂等重试和完成后刷新行为。

## 7. 视觉验收

- 1440×1000、1024×768、390×844 三档逐页截图。
- 无横向页面滚动、重叠、截断、菜单图标错位、路由切换跳动和空白 Canvas。
- 键盘可完成导航、筛选、弹窗确认和关闭；焦点可见并正确回到触发器。
- 中文最长文案与英文均不破坏表格、按钮、Tab、Breadcrumb 和 Drawer。
- 每个页面由截图检查布局、层级、密度、对齐、图标、状态色和交互稳定性后才能进入 E2E。

## 8. 完成条件

后端 API 契约已验收；所有菜单为真实能力；组件、集成、安全和构建测试通过；两轮可见浏览器
E2E 覆盖全部业务环节；报告包含分类、整体状态、本地/UTC 时间、步骤、截图、RPC/日志证据。
