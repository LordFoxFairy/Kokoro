## 两人并行规则与领取顺序

1. **开始即两条功能线并行**：A 从 A-01 / A-02 收口会话与展示，B 从 B-01 / B-02 收口 MCP / API，然后进入 Skills。每条线一次只推进一个可验收切片。
2. A-07 在会话首片收口后优先做；任务板可用后，通过正式 CRUD 登记这两份功能任务。登记前核已有项目 / 任务，避免重复创建；不直接 SQL 灌记录。只有真的回读成功才记录“已入面板”。
3. 两个人都可改相关前后端子仓；先声明任务 ID、具名文件和当前 diff，按文件隔离，不按前后端或整仓封锁。职责变更先在这两份任务表登记。
4. AppFrame / Composer / engine、BFF bootstrap、Agent factory、各机器契约、Schema、生成目录、lockfile、共用样式 / i18n 同时只由一个人写。当前功能负责人拿到文件写权后完成最小改动并交接；另一人先做不相交文件，不同时覆盖入口。不能手改 generated。
5. 两人互审。Root 集成、共享 index / 分支操作、统一进程启停由 **A 兼任集成者**，这是 A 本人兼任，不另设第三个人。B 交已停写的路径 / SHA 后 A 串行执行集成；独立 checkout 的子仓 Git 操作仍先约定，勿抢共享 index。
6. 相邻功能缺口交给对应负责人，但本功能能独立修的继续推进。已有授权和既定方案直接执行，不因本文新增审批或自设支出上限；新数据 / owner 决策按项目设计门收敛，独立工作继续。
