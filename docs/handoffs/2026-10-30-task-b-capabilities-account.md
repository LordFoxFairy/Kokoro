## 交接、验收与进度记录

1. 每次只领取一个可完成的业务切片，登记负责人、功能 ID、现有 diff、具体写区、完成条件和对方依赖。依赖不就绪只标明对应动作，独立可修项继续。
2. 状态采用 **待领取 → 进行中 → 待对方依赖 / 待验收 → 已验收待合并 → 已合并**。本组全部入口 / API / 持久化 / 恢复验证完成再关功能，不能页面做完就标完成。
3. 表内包含已有成功能力的后续验收项，不将旧记录的“未实现”照搬为当前缺陷。先核真实状态、复用已有证据，避免循环重做。当前不清楚的公开能力记“待核验 / 待裁决”，不擅自扩建。
4. 页面真实点击、owner 权威回读、刷新 / 重登、失败 / 并发 / 权限验证要配对；同状态 Manus 对照保留截图 / 布局 / 触发记录。受影响的键盘、窄屏、加载和性能随片验收，技术细节只留用户确实需要的地方。
5. 工程检查依实际子仓 AGENTS / README 和影响范围：迭代跑 focused / lint / types，完整需求交付跑相应格式 / contract / tests / build；涉及数据补隔离真实 schema / integration。mock 不称真实链，skip / 原失败据实报告，不能删断言制造通过。
6. 子仓 owner→固定 artifact→消费者按依赖交付，不使用 WIP 作为发行事实。完整需求复用一条 PR；按当前会话授权推进提交 / 推送 / 合并，不重复提问。共享 Git、正常服务和数据操作由 A 在现授权范围内串行做，未授权具体副作用再按规则处理。
7. B 负责本组任务记录；A-07 面板可用后由 A 经正式 CRUD 首次登记两组任务并核去重 / 回读，随后两人更新自己条目。文档仍是详细派工依据，不假称任务已入数据库。
