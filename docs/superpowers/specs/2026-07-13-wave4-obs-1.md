# Wave 4 · OBS-1 子 spec——session/agent 可观测(单 lane,不与其他项混)

状态:执行稿(上级=总设计稿 §6 Wave4,已获批)。纲领原文:session/agent metrics/tracing、卡死与
计费补偿告警。现状:两仓零 metrics(仅 console);Wave2 已埋 ERROR 告警日志(compensation_stuck/
receipt_state_lost/hold 临期)但无指标面与卡死检测。

## 范围(V1,务实不镀金)

1. **/metrics Prometheus 端点**:
   - session:prom-client(新依赖,理由=观测地基,标准库无;lockfile 变更如实报)。计数/直方图:
     run 受理/终态(按 code)、dispatch pending→claimed/expired、control outbox 状态迁移、
     durable 双水位滞后(persisted-projected gap gauge)、billing journal 相位计数(stuck 单列)、
     SSE 连接数、HTTP 请求时延直方图(按路由)。端点访问=internal(不进公网面;e2e/dev 直读)。
   - agent(worker):prometheus_client(同理)。计数:claim win/lose、inbox persisted/applied/
     superseded、outbox queued/published/republished/receipt_state_lost、tool journal
     unknown_outcome、MCP 连接失败/egress 拒绝;gauge:活跃 run 数、lease 持有数。worker 无 HTTP
     →起最小 http server(prometheus_client start_http_server,端口 env,缺省关)。
2. **卡死检测(session)**:reconciler 节奏扫 active run:最近事件时间距今 > env 阈值(缺省 10min)
   →ERROR 日志(含 run_id/session_id/最后 kind)+ metric 计数;不自动杀 run(V1 只告警)。
3. **计费补偿告警收口**:compensation_stuck/hold 临期已有 ERROR 日志→补 metric;stuck gauge>0
   即可被 Prometheus 告警规则消费(规则文件不在本项,留 OBS-2/部署)。
4. **tracing 不做**(V1):langfuse trace 已有留位(run.request.trace 直透),分布式 tracing 全套
   留后续;本项只 metrics+告警。在 spec 里明说,防镀金。

## 边界

不改任何业务语义/契约/存储形状;metrics 采集失败绝不影响主链路(try/except 包裹,fail-open);
不进 kokoro-web/platform;closure-up/gate 不加断言(指标面用两仓单测覆盖:端点 200+关键指标名
存在;e2e 只回归)。

## 验收

双仓全量只增不减三绿;新增依赖说明(prom-client/prometheus_client+lockfile);metrics 端点单测;
卡死检测故障注入测试(伪造陈旧 active run→告警+计数);全链 e2e 回归绿。
