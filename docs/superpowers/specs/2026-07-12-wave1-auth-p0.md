# Wave 1 · AUTH-P0 子 spec(纲领 D3 的工程落地)

状态:执行稿(上级=总设计稿 D3/§5.1/§7,已获批)。依赖:TRUST-ROUTES 合流(web-bff caller 凭据)。
仓面:kokoro-web(分支 agent/p2-auth-wiring)为主 + kokoro-user 微改(nonce 绑定)+ 主仓 closure-up/gate。

## 目标不变量(交付后必须全真)

浏览器不持 bearer(localStorage token 途径删除);任意邮箱直登不复存在;magic-link 原文 token 不落日志;
namespace/site 只能来自 user consume 响应;跨设备/无 nonce 打开链接统一 `auth_link_unavailable` 不泄露账号存在性。

## 分件

1. **web BFF 会话信封**(kokoro-web,Node runtime route handlers):
   - `KOKORO_WEB_SESSION_SECRET` 对 `{runtime_jwt, user_id, namespace, site_id, exp}` 签名加密(jose A256GCM 直封或 HS256 签名+加密二选一,选 jose EncryptJWT 单件);写入 `HttpOnly; SameSite=Lax; Path=/; Max-Age≤jwt exp; production 加 Secure` cookie。
   - 密钥 current+previous 双把轮换(env 逗号分隔),写 current 读双把。
2. **登录流**:
   - `POST /api/auth/magic-link/request {email}`:BFF 设一次性 HttpOnly nonce cookie,并把 nonce 哈希随请求交 user(user 侧 magic_links 表加 nonce_hash 列,consume 时校验——kokoro-user 微改+additive migration);site 固定服务端 `KOKORO_SITE_ID`,不收浏览器 site。
   - `GET /api/auth/callback?token=`:校验 nonce cookie 匹配→BFF 带 web-bff caller 凭据调 user consume→密封 cookie→**303 到 `/`**(无 token URL),响应 `Referrer-Policy: no-referrer`;nonce 缺失/不匹配/过期/consume 失败→统一 303 到 `/?auth=link_unavailable`(页面给重新发送入口)。
   - `POST /api/auth/logout`:同 path 立即过期 cookie。
   - 投递:user 侧已有 response|log 两档——**log 档改为只记 token 哈希前缀**(纲领:原文不落日志,user 微改);dev 端到端用 response 档由 BFF 转成"开发模式直接给可点链接"页面提示(仅 NODE_ENV!=production)。
3. **session 代理**(kokoro-web catch-all):`/api/session/[...path]` 读信封→注入 `Authorization: Bearer <runtime_jwt>`→透传 HTTP/SSE/二进制(files/deliveries 流式);mutation 校验同源 Origin。engine client baseUrl 改指同源 `/api/session`;`kokoro.auth.token` localStorage 读写全删;登录闸改探 `/api/auth/session-state`(有效信封=pass)。dev-login 路由删除(D1:不留兼容轴)。
4. **Hub BFF 占位**:`/api/hub/[...path]` 同信封取 namespace+internal secret 调 hub(实开在 HUB-AUTHZ/WEB-SKILLS,本项只落转发骨架+403 关闭态)。
5. **CORS 收口**:web 全走同源后,session 的 KOKORO_WEB_ORIGIN 仅供直连档保留;closure-up 改走 BFF(浏览器不再直连 3900)。

## 验证(纲领 §8.2-1/-11)

- vitest:信封封/验/过期/双钥轮换;nonce 绑定;代理注入与 SSE 透传(fixture session);logout。
- 浏览器实走(closure-up):request→(dev 档取链)→callback→cookie 会话→发消息→SSE 终态;**跨设备模拟**(清 nonce cookie 再开链接)→统一失败→当前浏览器重申请成功;localStorage 无 token 断言;日志无原文 token 断言(grep session/user 日志)。
- gate:不动既有直连断言(session Bearer 直连仍是合法部署形态);web 链证据以浏览器实走+截图交付。
