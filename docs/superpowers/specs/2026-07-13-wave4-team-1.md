## PLATFORM-USER(web-bff/admin 面,路由分级沿 TRUST-ROUTES)

1. **成员读面**:GET 本人 teams(含 role)/GET 团队成员列表(member 可读)。
2. **邀请流**:owner/admin POST 邀请{email,role∈[admin,member]}→invite 行(pending,token,过期);
   被邀者登录后(同 email principal)GET 本人 pending invites→accept/decline;accept→membership
   行(active)+invite 消费(幂等,过期/重复 accept 负向)。V1 不发邮件(SMTP=SEC-2 留位):邀请露出在
   被邀者登录后的界面,不生成邮件深链。
3. **成员权限**:owner 可改 role/移除成员;admin 可邀请/移除 member;不可移除最后一个 owner(负向);
   离队者 membership→inactive,hub authorizer(既有 /memberships/check)即时生效。
4. **团队换签**:POST 换签{team_id}——校验 caller principal 在该 team active→签发该 namespace 的
   runtime token(既有签发面复用,iss/site 校验不变)。web BFF 调它后重密封 cookie。
5. admin manifest 既有团队动作接真路由(点了即败→点了即真)。

## WEB(分支 agent/p2-auth-wiring)

- 团队切换器(信封里的当前 namespace 高亮;切换→BFF 换签→重密封 cookie→刷新水合:rail/技能/余额
  全部随 namespace 切换——Wave3 三竖切天然按 namespace 走,无需改它们)。
- 成员管理页(owner/admin:列表/邀请/改角色/移除;member:只读);pending invites 卡(accept/decline)。
- 浏览器实走:双用户两浏览器上下文——A 邀 B→B accept→B 切到 A 团队→B 看到 A 团队会话列表为空
  (B 自己的会话不串)→A 移除 B→B 换签该团队 403。截图 tmp/screenshots/wave4-team-*。

## 边界

  (只收换签后的 namespace token)。契约:无根契约变更(user 模块 API 属 platform 内面;若发现需
  上根契约立即停手上报)。
- TEAM-1 后 hub authorizer 逻辑不改(纲领:沿用同一 authorizer)。
