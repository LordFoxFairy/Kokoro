# Wave 4 · SEC-2 子 spec——签发链硬化(RS256/JWKS + magic-link Redis 限频)

状态:执行稿(上级=总设计稿 §6 Wave4,已获批)。仓面:platform-user + kokoro-session(+gate 环境)。
范围注:MCP secret:path 档已在 MCP-SECRET 废除,不在本项。

## RS256/JWKS

- **user(签发方)**:runtime token 签发换 RS256——私钥 env(PEM,KOKORO_USER_JWT_PRIVATE_KEY)+kid
  (=公钥指纹前 16hex);`GET /.well-known/jwks.json`(public 面)双 kid 轮换服务(当前+上一,
  KOKORO_USER_JWT_PRIVATE_KEY_PREVIOUS 可选);iss/site claim 不变。未配私钥→启动 fail-fast
  (生产)/退化 HS256(仅显式 dev 档,见下)。
- **session(验签方)**:auth 验签口收窄为部署模式 env `KOKORO_AUTH_MODE=jwks|hs256`:
  - jwks:按 token kid 从 KOKORO_AUTH_JWKS_URL 取键(内存缓存+TTL,未知 kid 强制刷新一次,仍未知
    =401;JWKS 不可达=fail-closed 401,ERROR 告警),只收 RS256。
  - hs256:既有共享 secret 档,**仅限 dev/test**:NODE_ENV=production 且 mode=hs256 → 启动
    fail-fast(纲领生产 fail-closed 语义;不留静默降级轴)。
- web BFF 不改(token 对它不透明,密封 cookie 原样)。
- **gate/closure 接线(缝合者自理)**:gate 主段(手签 e2e-user/bob)保持 hs256 档;E2E-40 段真签发
  链切 jwks——user 服务配测试 RSA 私钥(openssl 生成于 scratch,不入库),session2 KOKORO_AUTH_MODE=
  jwks 指向 user JWKS→「真签发→RS256→JWKS 验签→计费全链」成为门禁断言;再加负向:HS256 手签
  token 打 jwks 档 session2 → 401。

## magic-link Redis 限频

- user 的 magic-link 请求限频从内存 map 换 Redis(固定窗口或滑窗,键=email+ip 两维,阈值 env);
  Redis 不可达→fail-open 放行+WARN(登录可用性优先,限频是防滥用不是安全门,注释定案)。
- 同时收掉 AUTH-P0 留档的 magic-link log 明文 token(若仍在:token 只落 sha256 指纹)。

## 验收

user/session 全量只增不减三绿;新负向:未知 kid/过期 kid 轮换双读/JWKS 不可达 fail-closed/生产
hs256 fail-fast/限频阈值触发 429+窗口过后恢复/Redis 挂 fail-open;gate 全绿含 E2E-40 jwks 档
真链断言与 401 负向;e2e 其余段行为不变。
