## Slice A machine authority

`slice-a-contract-manifest.yaml` is a byte-for-byte installed copy of the reviewed Root design authority. The additive stream-establishment revision preserves `BrowserSessionEvent event = 1`, moves it into the `payload` oneof, and adds `StreamConversationEventsReady ready = 2`. Chat must finish caller authentication, IAM-derived authorization, conversation scope and cursor-retention validation before the first response; typed failures such as `SNAPSHOT_REQUIRED` occur before `ready`, while success yields exactly one `ready` immediately and then only events. The browser OpenAPI/SSE contract is unchanged because Web consumes `ready` internally. The earlier additive projection-NACK wire remains intact. The pre-handshake breaking image stays frozen; Buf retains `FILE` with only `FIELD_SAME_ONEOF` excepted, and `test_chat_stream_ready_compatibility.py` proves that specific migration byte-for-byte. The Root E2E consumer explicitly includes both IAM authentication and authorization so the native product-chain proof calls Refresh, Authorize and Logout through generated gRPC code; this test-only closure does not broaden the browser-facing Web consumer. Run:

    python3 contract/validate_slice_a_manifest.py contract/slice-a-contract-manifest.yaml

before rendering or generation. The validator is dependency-free and fail-closed. Proto/OpenAPI and declared consumer closures are rendered or generated only from this authority; child repositories never edit or copy it manually.

Generation keeps provenance honest in two commits. First commit this source authority, renderer output, registry and tests. From that exact clean source SHA, generate Root `root-e2e` with `contract/generate.py --consumer root-e2e --repo .` into a descendant-output commit; Chat and Web regenerate their declared closures from the same SHA (other consumers regenerate only when their closure changes). A dirty worktree SHA is never written into generated headers or `provenance.json`.
